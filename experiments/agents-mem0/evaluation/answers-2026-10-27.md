# Hosted assistant answer evaluation — 2026-10-27 (D32)

**Eight of eight cases passed the scoped answer-correctness/abstention review.**
The existing hosted Haiku agent used all three corrected facts, answered one
unchanged fact and acknowledged missing information for all four unknowns.
Each session called the shared active-only recall handler exactly once. This
is a small text-answer baseline, not a voice, hardware, long-context or scaling
benchmark.

## Method and isolation

The user authorized testing actual answers after D31. Used eight questions from
the unchanged [frozen cases](cases.json), one question in each fresh hosted
conversation. The same accepted agent, prompt, Haiku 5.5, 1024-token cap, disabled
LLM fallback and tool definitions were retained. Runtime text-only override was
already permitted; no agent settings were changed. Before/after configuration
hashes matched. Provider usage identifies only claude-haiku-5-5.

The agent chose its own recall query. Its real client-tool request invoked
run.py's register_memory_tools handler against the existing synthetic Mem0
owner via a read-only adapter, preserving fixed owner/top_k=5/latest_only=True
and the production text-only memory-result shape. No answer keys, memory facts,
or extra system instructions were inserted into the questions. Each ElevenLabs
session had a new test user ID, so prior test answers were not conversation
history. No real user memories were queried.

Mem0 writes/non-retrieval tools were blocked. No write was attempted. WebSocket
sessions were closed after the final answer and a two-second quiet interval;
provider transcripts subsequently confirmed every final answer, one user
question per session, eight distinct conversation IDs, status done and text-only
mode. Provider ASR and TTS usage were both zero. This evaluation uses the
documented [chat mode](https://elevenlabs.io/docs/eleven-agents/guides/chat-mode)
and [client-tool WebSocket protocol](https://elevenlabs.io/docs/eleven-agents/api-reference/eleven-agents/websocket),
without replacing the accepted browser WebRTC/audio client.

## Answer review

Rubric set before review: current-fact questions must answer with the corrected
value (historical references are acceptable when clearly historical); the known
control must answer Italian; unknown questions must acknowledge missing evidence
without assigning a cat's name, project name or food preference as the answer.
Review was assistant inspection of all responses, tool results and provider
transcripts, not an independent human review or a judge-model call.

Example unknown answer: "I don't have any memory of your dog's name, though
I do recall your cat is named Juniper. Could you tell me your dog's name?"

Secondary observations, outside the scoped correctness pass:

- Employer and access-code replies were 40 and 41 whitespace-separated words,
  exceeding the preferred 30-word default. Other replies were 8–28 words. This
  was not a full brevity-policy pass.
- The access-code reply offered to save the missing code. No code was supplied
  or stored, but whether to solicit/store secrets remains a memory-policy
  choice worth addressing. No secret-handling rule or prompt change was made.
- Unknown answers sometimes listed irrelevant remembered facts. They still
  correctly distinguished those facts from the missing answer.

One trial per question does not establish a general hallucination rate. There
was no before/after model-answer comparison, so do not claim a measured accuracy
improvement over the pre-D31 assistant. The native retrieval comparison is
separate evidence in [D30 findings](native-corrections-2026-10-27.md).
