# whisper-stack dependencies — single install profile after the Gemini
# migration. The two-file local/cloud split (and `requirements-cloud.txt`)
# is gone; there's only one deploy shape now.
#
# Local-only system bits the pip install does NOT cover (document in CLAUDE.md):
#   * NVIDIA CUDA / cuBLAS / cuDNN wheels — needed at faster-whisper import.
#     On Windows the per-process `os.add_dll_directory` shim in
#     server/backends/stt_whisper.py points at site-packages/nvidia/*/bin.
#   * Kokoro ONNX model + voices — drop kokoro-v1.0.onnx and voices-v1.0.bin
#     under models/kokoro/. Both are downloadable from
#     https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.0
#     (model ~310 MB, voices ~27 MB). Set KOKORO_VOICE in .env to override
#     the default af_bella.
#   * Piper voice models (rollback path) — drop the .onnx + .json files under
#     models/piper/ and set PIPER_VOICE in .env.
#   * openwakeword's bundled models — `python -c "import openwakeword;
#     openwakeword.utils.download_models()"` once per machine.

flask
python-dotenv
requests
numpy

# LLM (cloud)
google-genai

# STT (local, GPU)
faster-whisper

# TTS (local). Kokoro 82M ONNX path is the active default; Piper stays as
# the rollback (switch by editing server/modes.py:get_tts() back to
# PiperTTS). kokoro-onnx is preferred over the official `kokoro` package
# because `kokoro` hard-pins numpy==1.26.4 which has no Python 3.13
# wheel; this ONNX path is pure-Python over onnxruntime and bundles its
# own espeak-ng so no system install is needed.
kokoro-onnx
piper-tts

# Wake-word detection (server-side, used by /listen for the ESP-32 firmware
# and tests/jarvis.py).
openwakeword

# Local audio playback (server speaks the reply when play_locally=true).
sounddevice

# tools/time.py uses zoneinfo + IANA tz database. Linux usually ships these
# at the OS level; this Python package is the cross-platform fallback (also
# required on Windows venvs).
tzdata
